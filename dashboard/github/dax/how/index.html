How it works

Two parts, and the catalog between them as the contract. Each card is what this page just ran, in your browser.

← → step through← dashboard
writes → → reads

dbt-duckdb, run every hour by GitHub Actions: it downloads AEMO's files, loads them as they are published into landing, and builds the mart tables (dimensions, facts, daily and monthly aggregates) that it writes as Iceberg tables to OneLake, through the catalog. Everything a report reads is a mart table. Open the dbt docs

The contract between the two parts: the mart tables, their columns and their types, in an Iceberg catalog (OneLake). Data engineering writes them and knows nothing of the reports; every client reads them and knows nothing of dbt: Power BI in Direct Lake, this page through copies of the same tables. The semantic model is built on this contract: one dataset per table.
